# 25. 개발 태스크 플랜 (순차·병렬 구성)

> 이 플랜의 태스크를 Phase 순서대로(Phase 안에서는 트랙별로 병렬) 완료하면 **소프트 런치 빌드**가 나온다. 날짜는 적지 않는다. 각 태스크는 `ID · 목표 · 입력(문서/데이터) · 산출물 · 완료 기준 · 선행 · 병렬`로 정의한다. 완료 기준은 [24 §5 검증 게이트](24_개발_시작_가이드.md)를 따른다. 진행은 §11 체크리스트에 표시한다.

## 0. 읽는 법
- **트랙**(한 사람이 한 트랙을 이어서 맡기 좋다): **P** 준비 · **C** 전투 코어 · **V** 전투 뷰 · **D** 데이터·임포터 · **M** 메타 서비스 · **U** UI 화면 · **N** 서버 · **A** 아트·오디오·VFX · **L** 콘텐츠(대본·컷신·로컬라이즈) · **B** 밸런스 · **Q** QA·릴리즈.
- **Phase 0~6**: 각 Phase 끝에 **게이트**가 있다. 게이트를 넘기 전에는 다음 Phase의 크리티컬 패스 태스크를 시작하지 않는다(병렬 트랙은 먼저 가도 된다).
- `선행`은 반드시 끝나야 하는 태스크, `병렬`은 같은 시기에 함께 진행하기 좋은 태스크.
- 1인 개발이면 §9 "권장 단독 순서", 2~3인이면 §10 "병렬 묶음"을 따른다.
