# 09. 밸런스 시뮬레이션 (등가모델)

> 목표 2의 밸런스 설계: "게임 구성이 완료된 후 등가모델로 시뮬레이션을 개발해 영웅과 아이템의 수치·스킬을 설계한다."
> 구현: `sim/engine/`(전투 엔진), `sim/run_balance.py`(밸런스 러너), `sim/validate_battles.py`(전투 난이도 검증), `sim/report_md.py`(보고서).
> 결과 부록: [B1 영웅 밸런스](appendix/B1_영웅_밸런스.md), [B2 아이템 밸런스](appendix/B2_아이템_밸런스.md), [B3 전투 난이도 검증](appendix/B3_전투_난이도_검증.md).

## 1. 등가모델(Equivalence Model)이란
"같은 계층·같은 성급의 영웅은 같은 가치여야 한다"는 원칙을 **측정 가능한 지표**로 바꾼 것이다.

| 등가 단위 | 정의 | 목표 |
|---|---|---|
| 영웅 (계층 t, 성급 s) | 같은 계층 영웅끼리 무작위 5v5 팀을 짜서 싸울 때 그 영웅이 **참전한 팀의 승률**(present win-rate) | 50% ± 5%p (★1·★2·★3 각각) |
| 계층 간 | 계층 t ★s 팀 vs 계층 t+1 ★1 팀 승률 | TFT와 동일한 구조(상위 계층 ★1 > 하위 계층 ★1, 하위 계층 ★2 > 상위 계층 ★1)를 보고로 확인 |
| 아이템 (분류 c) | 계층 3 기준 팀 6종의 교차전(5v5, ★1·★2)에서 캐리어 1명에게 아이템 1개를 장착했을 때의 승률 상승분 Δ | 분류별 목표 Δ ± 3%p (조합 +11, 빛나는 +20, 유물 +14, 지원 +8, 국가 특산 +12) × 캐리어 역할 보정(탱커 1.5, 브루저 1.25) |
| 전투 난이도 | 레벨에 맞는 "기대 팀"의 난이도별 승률 | 보통 70~85%, 어려움 45~65%, 악몽 20~40% |

승률을 지표로 쓰는 이유: 피해량·치유량 같은 단일 지표는 역할(탱커·힐러·버퍼)마다 의미가 달라 비교할 수 없지만, "그 영웅이 있을 때 팀이 이기는가"는 모든 역할을 같은 잣대로 잰다. 무작위 팀 편성은 특정 시너지/조합 편향을 평균화한다(TFT 통계 사이트의 '유닛 승률'과 같은 개념).

## 3. 영웅 밸런스 알고리즘
```
입력: heroes.json (설계 기본값: 직업 템플릿 × 계층 배율 × ±4% 개성 지터)
반복 i = 1..N:
  각 계층 t, 각 성급 s ∈ {1,2,3}:
    같은 계층 영웅으로 무작위 5v5 팀을 (영웅당 참전 500회가 되도록) 생성, 아이템 없음
    전투 → 영웅별 참전 승률 wr(h, s)
  영웅별 조정: f = (0.5 / wr)^0.42, 1회 변화 ±15%로 제한, |wr-0.5| ≤ 2%p면 조정 없음
    balance.star_mult[s] *= f   (성급별 HP·AD·스킬 수치에 공통 적용 → 콘셉트 유지, 전력만 조정)
  종료: 세 성급 모두 ±5%p 밴드 내 영웅 비율 ≥ 96%
정밀 단계: 참전 1,200회, 지수 0.3, 변화 ±8%로 6회 추가 반복(표본 잡음 수준까지 수렴)
최종 평가: ★1 600회, ★2/★3 400회, 1v1 라운드로빈(★2), 계층 간 교차 전력
```
- **왜 성급별 배율인가**: TFT와 같이 체력 ×1.8/성, 공격력 ×1.5/성이 고정이면 물리 딜러는 ★3에서 과도하게 강해지고 주문 딜러·힐러는 상대적으로 약해진다. 성급별 배율(★1/★2/★3 각각)은 TFT 디자이너가 성급별 스킬 수치를 따로 잡는 것과 같은 자유도를 준다.
- **왜 HP·AD·스킬에 같은 배율인가**: 영웅의 "느낌"(탱커인지, 포킹인지)은 직업 템플릿과 스킬 원형이 결정한다. 밸런스 단계는 그 느낌을 바꾸지 않고 전력만 맞춘다. 필요 시 디자이너가 `hp_mult/ad_mult/skill_mult`로 개별 방향 조정 가능.
- 표본 잡음: 참전 n회의 승률 표준오차 ≈ √(0.25/n). n=500 → 2.2%p, n=1,200 → 1.4%p. 따라서 sd ≈ 0.03 이하는 잡음 수준이며, 더 줄이려면 표본을 늘려야 한다.

## 4. 아이템 밸런스 알고리즘
```
기준 팀 6종: 계층 3 영웅으로 [탱커, 브루저, 물리딜러, 주문딜러(마법사·주술사), 지원] 역할 구성(무작위)
아이템 i (조합 55, 빛나는 55, 유물 60, 지원 30, 국가 특산 24 = 224종):
  캐리어 역할 = 아이템의 능력치/훅에서 추론(물리 → 물리딜러, 주문/마나 → 주문딜러, 방어 → 탱커, 흡혈 → 브루저, 오라 → 지원; 최대 2역할)
  기준 팀 × 40회: 캐리어에 아이템 1개 vs 동일 팀(아이템 없음) → 승률
  Δ = 승률 - 기준선(아이템 없는 미러전 승률, 배치 비대칭 보정)
조정: f = ((목표Δ+0.05)/(Δ+0.05))^0.6, ±20~25% 제한 → items.balance.mult *= f
  mult는 아이템의 모든 능력치와 훅의 수치 파라미터에 곱해진다(설명 문구의 수치는 기본값 기준).
반복 8회(이전 결과에서 이어서), 최종 평가 매치업당 6회
```
- 상징(특성 부여)과 특수 아이템(팀 슬롯)은 수치 밸런스 대상이 아니다(조합 재료 능력치 그대로).
- 전투 외 효과(골드·드랍률·스태미너)는 경제 계층에서 설계한다([07](07_경제_및_비즈니스모델.md)).

## 5. 전투 난이도 검증
- 지역·스토리 전투에서 240개를 표본 추출, 각 3난이도 × 12회. 적은 `battles.json`의 편성(몬스터 템플릿 + 보스 체력 배수 + 난이도 성급)으로, 아군은 "레벨에 맞는 기대 팀"(계층 = 1 + 레벨/22, 성급 = 레벨 35 미만 ★1 / 75 미만 ★2 / 이상 ★3, 역할 혼합 6인)으로 생성.
- 난이도의 적 전력 배수(1.0/1.6/2.6)는 성급 상승으로 대부분 구현되고, 잔여분만 능력치에 곱한다.
- **몬스터 전력 보정 곡선**: 난이도 × 레벨 10 구간(30칸)마다 몬스터 HP·AD·AP 배수를 피팅한다(목표 보통 78% / 어려움 55% / 악몽 30%, 지수 0.3, 라운드당 ±20~25%, 6라운드). 결과는 `economy.json`의 `enemy_power_curve`에 저장되어 클라이언트가 적 생성 시 곱한다. 기대 팀의 성급이 레벨 35·75에서 계단식으로 오르므로 곡선도 그 지점에서 꺾인다.

## 7. 해석과 후속 작업

### 7.1 영웅
- 196명 전원이 세 성급(★1/★2/★3)에서 참전 승률 50% ± 5%p 밴드에 93~95% 들어갔고, 표준편차 0.025~0.028은 표본 잡음(600회 ≈ 2.0%p, 400회 ≈ 2.5%p)과 같은 수준이다. 밴드 밖 영웅은 잡음 범위이며 실서비스 데이터(픽률·승률)로 2차 보정한다.
- 계층 간 구조는 TFT와 동일: 상위 계층 ★1 팀이 하위 계층 ★1 팀을 92~100% 이기고, 하위 계층 ★2 팀이 상위 계층 ★1 팀을 99~100% 이긴다. 5v5 팀전은 소폭의 전력 차도 승률로 크게 증폭된다.
- **설계 기본값 대비 원형별 보정**이 곧 설계 피드백이다: 도발·방어막 계열(taunt_shield 0.69, shield_self 0.74, shield_allies 0.77)은 기본값이 과강, 아군 버프 계열(buff_ap_allies 1.61, buff_ad/as_allies 1.40)과 소환(1.24)·지속 피해(1.25)는 과약이었다. 이 비율을 `gen_heroes.py`의 원형 기본값에 접어 넣으면 재생성 시 보정량이 줄어든다(후속).

### 7.2 아이템
- 분류별 평균 Δ는 역할 보정 목표의 ±2%p 안에 들어왔다(조합 +0.143 vs +0.124, 빛나는 +0.232 vs +0.226, 유물 +0.177 vs +0.155, 지원 +0.098 vs +0.080, 특산 +0.164 vs +0.135).
- **전열 아이템의 구조적 강함**: 탱커 캐리어의 방어형 아이템(가고일 돌갑옷·가시 갑옷·불사의 심장·불멸의 갑주 등)은 능력치를 40%까지 낮춰도 Δ +0.2~0.3을 유지한다. 전열이 무너지면 팀이 지는 TFT식 전투의 성질이며, 그래서 목표 Δ에 탱커 1.5배 보정을 두었다. 그래도 한계(배율 0.4)에서 목표 밖인 24개는 `balance.flag = context_dependent`로 표시했다 → 수치가 아니라 효과를 바꿔야 한다(예: 부활은 체력 %가 아니라 '부활 후 N초 피해 불가' 삭제, 고정 피해 처형은 임계값 하향).
- 반대로 상황 의존형 과약 아이템(용의 발톱·암살자의 가면·용살자의 장검·공성 사다리·보급 마차·드랍 부적류)은 마법 딜러 비중, 고체력 적, 웨이브/구조물 전투, 전투 외 보상에 가치가 있어 교차전 평가에서는 저평가된다. 이들은 배율 상한(2.0)에서 고정하고 유형별 전투(공성·방어·레이드) 시뮬레이션으로 따로 검증한다(후속).

### 7.3 전투 난이도
- 기대 팀 기준 평균 승률 보통 78.9% / 어려움 54.8% / 악몽 34.0%로 목표 밴드 안이다. 레벨 61~100 구간은 기대 팀이 ★3·계층 4~5로 계단식 상승해 아직 목표보다 높다(어려움 84%, 악몽 53%). 보정 곡선은 6라운드에서 수렴 중이며 라운드를 늘리거나, 고레벨 기대 팀 정의를 '★2 혼합'으로 낮추면 해결된다.
- `economy.json`의 `enemy_power_curve`(난이도 × 레벨 10 구간, 30개 배수)는 클라이언트가 적 생성 시 HP·AD·AP에 곱하는 라이브 튜닝 값이다. 전투 데이터(`battles.json`)를 바꾸지 않고 난이도를 조정할 수 있다.

### 7.4 후속 작업
1. 원형 기본값에 보정 비율 반영 후 재수렴(설계값 정규화).
2. 아이템 2~3개 동시 장착 상호작용과 특성 임계값(2/4/6/8) 가치 측정.
3. 상황 의존형 아이템의 유형별 전투 시뮬레이션(공성·방어·레이드·구조물).
4. 스토리 결전 보스 전투 수동 튜닝, C# 포팅 후 테스트 벡터 동기화.

## 8. 후속 작업 방법 (2차)

| 작업 | 방법 | 스크립트 |
|---|---|---|
| ① 원형 전력 계수 반영 | 1차 측정된 원형별 ★1/★2/★3 평균 배율을 `gen_heroes.ARCHETYPE_POWER`(설계 상수)로 접어 넣고 영웅별 배율을 초기화한 뒤 재수렴. 영웅 JSON에 `archetype_power`가 기록되고 `balance.star_mult`는 잔여분만 담는다 | `tools/gen_heroes.py`, `sim/run_hero.sh` |
| ② 특성 임계값 가치 | 특성 T 레벨 L 보유 8인 팀 vs 계층 1:1 매칭 무작위 팀(보유자 제외). 같은 시드로 특성 활성/비활성 두 번 싸운 승리 차이의 평균 = 한계 가치(편성 강약과 분리). 목표 출신 2/4/6/8 → +5/+12/+20/+28%p, 직업 2/4/6 → +6/+15/+25%p. `traits.json` effects에 `balance.mult[레벨]` 배율(리스트형 수치에만 곱함), 3회 반복 | `sim/run_traits.py` |
| ③ 아이템 다중 장착 | 같은 캐리어 역할의 조합 아이템 2개(240)·3개(120) 무작위 조합. 시너지 = Δ조합 − ΣΔ단일 | `sim/run_item_combos.py` |
| ④ 상황 의존형 아이템 | 플래그 아이템을 5개 시나리오(마법 중심 적, 계층 5 보스 ×4, 적 성벽, 3웨이브, 암살자 캐리어)에서 재평가 → 상황 특화 OK / 전반 과강 / 재설계 필요 판정 | `sim/run_context_items.py` |
| ⑤ 보스 튜닝 | 결전·레이드·토벌형 스토리 전투의 보스 체력 배수(보통 승률 기준, 1~5)와 난이도별 적 전력 배수 `tuned_power_mult`(0.35~1.5)를 보통 65%/어려움 45%/악몽 25% 목표로 4라운드 조정, `battles.json`에 기록. 기대 팀 인원은 참전 모드 기준(단독 1·소대 4·부대 6·대군 8, 레벨 70+ 대군 10) | `sim/tune_bosses.py` |
| ⑥ 고레벨 보정 | 기대 팀을 레벨 75+에서 ★3·★2 혼합으로 정의하고 전투 유형 규칙(웨이브·성벽·수호 대상·호위·암살·탈출·구출)을 엔진에 구현해 8라운드 재보정 | `sim/scenario.py`, `sim/validate_battles.py` |
