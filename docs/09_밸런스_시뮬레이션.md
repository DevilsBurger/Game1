# 09. 밸런스 시뮬레이션 (등가모델)

> 목표 2의 밸런스 설계: "게임 구성이 완료된 후 등가모델로 시뮬레이션을 개발해 영웅과 아이템의 수치·스킬을 설계한다."
> 구현: `sim/engine/`(전투 엔진), `sim/run_balance.py`(밸런스 러너), `sim/validate_battles.py`(전투 난이도 검증), `sim/report_md.py`(보고서).
> 결과 부록: [B1 영웅 밸런스](appendix/B1_영웅_밸런스.md), [B2 아이템 밸런스](appendix/B2_아이템_밸런스.md), [B3 전투 난이도 검증](appendix/B3_전투_난이도_검증.md).

## 1. 등가모델(Equivalence Model)이란
"같은 계층·같은 성급의 영웅은 같은 가치여야 한다"는 원칙을 **측정 가능한 지표**로 바꾼 것이다.

| 등가 단위 | 정의 | 목표 |
|---|---|---|
| 영웅 (계층 t, 성급 s) | 같은 계층 영웅끼리 무작위 5v5 팀을 짜서 싸울 때 그 영웅이 **참전한 팀의 승률**(present win-rate) | 50% ± 5%p (★1·★2·★3 각각) |
| 계층 간 | 계층 t ★s 팀 vs 계층 t+1 ★1 팀 승률 | TFT와 동일한 구조(상위 계층 ★1 > 하위 계층 ★1, 하위 계층 ★2 > 상위 계층 ★1)를 보고로 확인 |
| 아이템 (분류 c) | 계층 3 기준 팀 미러전(5v5)에서 캐리어 1명에게 아이템 1개를 장착했을 때의 승률 상승분 Δ | 분류별 목표 Δ ± 3%p (조합 +11, 빛나는 +20, 유물 +14, 지원 +8, 국가 특산 +12) |
| 전투 난이도 | 레벨에 맞는 "기대 팀"의 난이도별 승률 | 보통 70~85%, 어려움 45~65%, 악몽 20~40% |

승률을 지표로 쓰는 이유: 피해량·치유량 같은 단일 지표는 역할(탱커·힐러·버퍼)마다 의미가 달라 비교할 수 없지만, "그 영웅이 있을 때 팀이 이기는가"는 모든 역할을 같은 잣대로 잰다. 무작위 팀 편성은 특정 시너지/조합 편향을 평균화한다(TFT 통계 사이트의 '유닛 승률'과 같은 개념).

## 2. 시뮬레이터
- 결정론적 자동전투(시드 고정), TFT 규칙([08 전투 시스템](08_전투_시스템.md)). 헥스 8×7, 틱 0.05초, 30초 + 연장 15초.
- 구현 범위: 스킬 원형 34종 전부, 출신 14·직업 14 특성 전부, 아이템 훅 55종(전투 외 효과 제외), 소환수·포탑·구조물, 처형·부활·무적 등.
- 성능: 6v6 전투 1회 ≈ 5ms(순수 Python, 1코어). 4코어 기준 계층별 5v5 500회 참전 평가 ≈ 25초.
- 테스트: `tests/test_sim.py` (헥스 거리, 피해 공식, 마나/시전, 결정론, 원형·아이템 전수 실행, 특성 활성).

## 3. 영웅 밸런스 알고리즘
```
입력: heroes.json (설계 기본값: 직업 템플릿 × 계층 배율 × ±4% 개성 지터)
반복 i = 1..N:
  각 계층 t, 각 성급 s ∈ {1,2,3}:
    같은 계층 영웅으로 무작위 5v5 팀을 (영웅당 참전 500회가 되도록) 생성, 아이템 없음
    전투 → 영웅별 참전 승률 wr(h, s)
  영웅별 조정: f = (0.5 / wr)^0.42, 1회 변화 ±15%로 제한, |wr-0.5| ≤ 2%p면 조정 없음
    balance.star_mult[s] *= f   (성급별 HP·AD·스킬 수치에 공통 적용 → 콘셉트 유지, 전력만 조정)
  종료: 세 성급 모두 ±5%p 밴드 내 영웅 비율 ≥ 96%
정밀 단계: 참전 1,200회, 지수 0.3, 변화 ±8%로 6회 추가 반복(표본 잡음 수준까지 수렴)
최종 평가: ★1 600회, ★2/★3 400회, 1v1 라운드로빈(★2), 계층 간 교차 전력
```
- **왜 성급별 배율인가**: TFT와 같이 체력 ×1.8/성, 공격력 ×1.5/성이 고정이면 물리 딜러는 ★3에서 과도하게 강해지고 주문 딜러·힐러는 상대적으로 약해진다. 성급별 배율(★1/★2/★3 각각)은 TFT 디자이너가 성급별 스킬 수치를 따로 잡는 것과 같은 자유도를 준다.
- **왜 HP·AD·스킬에 같은 배율인가**: 영웅의 "느낌"(탱커인지, 포킹인지)은 직업 템플릿과 스킬 원형이 결정한다. 밸런스 단계는 그 느낌을 바꾸지 않고 전력만 맞춘다. 필요 시 디자이너가 `hp_mult/ad_mult/skill_mult`로 개별 방향 조정 가능.
- 표본 잡음: 참전 n회의 승률 표준오차 ≈ √(0.25/n). n=500 → 2.2%p, n=1,200 → 1.4%p. 따라서 sd ≈ 0.03 이하는 잡음 수준이며, 더 줄이려면 표본을 늘려야 한다.

## 4. 아이템 밸런스 알고리즘
```
기준 팀 6종: 계층 3 영웅으로 [탱커, 브루저, 물리딜러, 주문딜러, 지원] 역할 구성(무작위)
아이템 i (조합 55, 빛나는 55, 유물 60, 지원 30, 국가 특산 24 = 224종):
  캐리어 역할 = 아이템의 능력치/훅에서 추론(물리 → 물리딜러, 주문/마나 → 주문딜러, 방어 → 탱커, 흡혈 → 브루저, 오라 → 지원; 최대 2역할)
  기준 팀 × 40회: 캐리어에 아이템 1개 vs 동일 팀(아이템 없음) → 승률
  Δ = 승률 - 기준선(아이템 없는 미러전 승률, 배치 비대칭 보정)
조정: f = ((목표Δ+0.05)/(Δ+0.05))^0.6, ±20~25% 제한 → items.balance.mult *= f
  mult는 아이템의 모든 능력치와 훅의 수치 파라미터에 곱해진다(설명 문구의 수치는 기본값 기준).
반복 4회, 최종 평가 60회
```
- 상징(특성 부여)과 특수 아이템(팀 슬롯)은 수치 밸런스 대상이 아니다(조합 재료 능력치 그대로).
- 전투 외 효과(골드·드랍률·스태미너)는 경제 계층에서 설계한다([07](07_경제_및_비즈니스모델.md)).

## 5. 전투 난이도 검증
- 지역·스토리 전투에서 240개를 표본 추출, 각 3난이도 × 12회. 적은 `battles.json`의 편성(몬스터 템플릿 + 보스 체력 배수 + 난이도 성급)으로, 아군은 "레벨에 맞는 기대 팀"(계층 = 1 + 레벨/22, 성급 = 레벨 35 미만 ★1 / 75 미만 ★2 / 이상 ★3, 역할 혼합 6인)으로 생성.
- 난이도의 적 전력 배수(1.0/1.6/2.6)는 성급 상승으로 대부분 구현되고, 잔여분만 능력치에 곱한다.

## 7. 해석과 후속 작업
- 모든 영웅의 참전 승률이 세 성급에서 50% ± 5%p 밴드에 대부분 들어갔다. 밴드 밖 영웅은 표본 잡음(±2%p) 수준이며, 실서비스에서는 플레이 데이터(픽률·승률)로 2차 보정한다.
- 계층 간 구조는 TFT와 동일하게 "상위 계층 ★1 > 하위 계층 ★1", "하위 계층 ★2 > 상위 계층 ★1"로 유지된다(5v5 팀전은 소폭의 전력 차도 승률로 크게 증폭된다).
- 아이템은 분류별 목표 Δ로 수렴했다. 같은 분류 안에서 Δ가 유사하므로 "어떤 아이템을 고르든 손해가 없고, 역할 적합성이 선택 기준"이 된다.
- 후속: (1) 아이템 2~3개 동시 장착 상호작용, (2) 특성 임계값별 시너지 가치(2/4/6/8) 측정, (3) 스토리 결전 보스 전투의 수동 튜닝, (4) C# 포팅 후 테스트 벡터 동기화.

```bash
python3 sim/run_balance.py --phase hero --iters 14 --appearances 500                      # 1차 수렴 (~7분, 4코어)

```
