# 10. 기술 사양 및 데이터 스키마

## 1. 플랫폼
| 항목 | 사양 |
|---|---|
| 엔진 | Unity 6 LTS, 2D URP, C# |
| 플랫폼 | iOS 15+ / Android 9+ (API 28+) |
| 화면 | **가로(Landscape Left/Right) 고정**. 기준 1920×1080(16:9). 지원 비율 4:3 ~ 21:9. Safe Area 대응(노치/펀치홀) |
| 해상도 전략 | Canvas Scaler: Scale With Screen Size, Match 0.5. 보드는 세로 높이 기준 스케일(7행 헥스가 화면 높이 80%) |
| 프레임 | 60fps 목표(전투), 30fps 로비 허용 |
| 용량 | 초기 다운로드 ≤ 150MB, 어드레서블로 국가별 에셋 지연 로드 |
| 저장 | 서버 권위(계정·보유·재화). 전투 결과는 서버가 동일 시드로 재시뮬레이션하여 검증(치트 방지) |

## 2. 아키텍처
```
[Client Unity]
  ├─ Data Layer: data/*.json 로드 (Addressables, 버전 체크)
  ├─ Meta: 로비·상점·편성·퀘스트 상태 (서버 동기화)
  ├─ Combat Core (C#, 결정론): sim/engine 포팅. 순수 로직, 렌더 분리
  ├─ Combat View: 헥스 보드, 유닛 스프라이트(2D 스켈레탈), 이펙트, 배속
  └─ UI (UGUI/UI Toolkit)
[Server]
  ├─ Account / Inventory / Economy
  ├─ Battle Verify: 같은 시드로 Combat Core 실행(C# 서버 또는 Python 레퍼런스)
  └─ LiveOps: 현상금 게시판, 시즌, 밸런스 데이터 핫픽스(JSON 배포)
```

## 4. JSON 스키마

### 4.1 heroes.json
```jsonc
{ "version": 1, "count": 196, "player_unit": {...},
  "heroes": [{
    "id": "H001", "name_ko": "로이드 하트윈", "name_en": "Lloyd Hartwin", "title": "성기사단장",
    "origin": "astel", "class": "guardian", "tier": 5, "rarity": "전설",
    "stats": { "hp": 1289, "ad": 82, "attack_speed": 0.556, "armor": 62, "mr": 67, "range": 1,
               "mana_start": 50, "mana_max": 110, "crit_chance": 25, "crit_damage": 140, "ap": 100 },
    "star_scaling": { "hp": [1.0, 1.8, 3.24], "ad": [1.0, 1.5, 2.25] },
    "skill": { "name": "왕국의 방벽", "archetype": "shield_allies", "desc": "...",
               "params": { "kind": "shield", "shield": [306, 459, 714], "target": "adjacent_allies", "duration": 5 } },
    "lore": "...", "balance": { "hp_mult": 1.0, "ad_mult": 1.0, "skill_mult": 1.0 }
  }] }
```
최종 능력치 = stats × balance 배율 × 성급 배율. `balance`는 시뮬레이션이 기록한다(수작업 금지).

### 4.2 traits.json
origins[14] / classes[14]: `{ key, name_ko, desc, synergy_desc, thresholds[], effects{hook, ...수치 배열} }`, archetypes(스킬 원형 기본값), class_base, tier_mult.

### 4.3 items.json
```jsonc
{ "id": "I008", "name_ko": "무한의 대검", "category": "completed",
  "stats": { "ad_pct": 10, "crit": 20 }, "hooks": [{ "type": "crit_dmg_bonus", "params": { "pct": 30 } }],
  "desc": "...", "price_gold": 900, "recipe": ["C01", "C08"] }
```
category: component | completed | emblem | radiant | artifact | support | national | consumable | material. stats 키: ad_pct, ap, hp, armor, mr, as_pct, mana, crit, omnivamp, durability.

### 4.4 nations.json
`{ key, name_ko, name_en, region_group, category, civilization, danger(1~10), capital, ruler, desc, native_origin, act, regions[5], enemy_factions[], battle_count, national_item }`

## 5. 전투 코어 인터페이스 (C# 포팅 기준)
```csharp
public sealed class BattleSetup {
  public int Seed; public BattleRules Rules;            // 유형별 규칙(웨이브·구조물·시간)
  public List<UnitSpec> Allies, Enemies;                // id, heroId|monsterKey, star, items[], (col,row)
}
public sealed class BattleResult { public bool Win; public float Time; public Dictionary<int, UnitStats> Stats; public List<ReplayEvent> Events; }
BattleResult Run(BattleSetup setup);                    // 순수 함수, 렌더 무관
```
- 고정소수점 또는 float 결정론: 플랫폼 간 동일성을 위해 정수 밀리 단위(hp×1000) 연산 권장. Python 레퍼런스는 float이며, 테스트 벡터는 승패·생존 유닛·시간(±0.1초)만 비교한다.

## 6. 성능 목표
- 전투 1회(10v10, 30초) 시뮬레이션 ≤ 20ms(C#), 스킵 시 즉시 결과.
- 서버 검증: Python 레퍼런스 ≈ 5~15ms/전투(순수 Python). 피크 1,000 TPS 시 워커 20대.

## 7. 네트워크/보안
- 전투 시작: 서버가 시드·편성 스냅샷 발급. 종료: 클라이언트 결과 + 서버 재시뮬 비교. 불일치 시 서버 결과 채택.
- 모든 보상 지급은 서버. 드랍 확률·호감도는 서버 RNG.

## 8. 로컬라이제이션
- 기본 한국어, 영어 병기 데이터(name_en). 텍스트 키는 id 기반(`hero.H001.name`). 폰트: Noto Sans KR / Noto Sans.
