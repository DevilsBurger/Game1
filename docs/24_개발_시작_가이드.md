**절대 규칙 6개**
1. 전투 코어는 `double` + xorshift64\* RNG, 파이썬과 같은 식·같은 순서로 계산한다. `float`, `Mathf`, Burst fast-math, FMA 자동 결합 금지. `Math.Round`는 `MidpointRounding.ToEven`.
2. `unity/Generated/*`, `data/*.json`, `docs/appendix/*`, `data/strings_*` 등 **생성 산출물은 손으로 고치지 않는다**. 원본(`tools/`, `design/`, `server/`)을 고치고 재생성한다.
3. 데이터 ID는 문자열 그대로 쓴다(H001, P000, I008, S001, B0101, HQ001). 열거형으로 바꾸지 않는다(핫픽스 호환).
4. 재화·보상·드랍·호감도·승급은 **서버 권위**다. 클라이언트는 표시만 하고, 낙관적 UI를 하지 않는다.
5. 문자열은 전부 Localization 키(`data/strings_unity.csv`)로. 하드코딩 금지.
6. 모든 변경 POST에는 `Idempotency-Key`. 오프라인 큐는 같은 키로 재전송한다.

## 3. 작업 프로세스 — 변경 유형별 흐름
### 3.1 게임 데이터 정의 변경(영웅·아이템·전투·퀘스트)
```
tools/roster_data.py·world_data.py·story_data.py (정의 수정)
 → python3 tools/gen_heroes.py / gen_items.py / gen_world.py
 → python3 tools/gen_schemas.py --validate && python3 -m pytest tests -q
 → (gen_heroes를 돌렸으면) sh sim/run_hero.sh && python3 sim/run_traits.py …   # 밸런스 배율 복원
 → python3 tools/export_md.py && python3 tools/gen_strings.py && python3 tools/gen_csharp.py
 → Unity: Assets/_Project/Data/Json 갱신 → 에디터 메뉴 Arken ▸ Import JSON (JsonImporter) → EditMode 데이터 테스트
```
- 스토리 전투 편성을 바꾸려면 `gen_world.py`의 `STORY_COMP_OVERRIDES`에 전투 ID를 추가하고 `sim/tune_bosses.py --scope story --ids …`로 재튜닝한다.

### 3.2 밸런스 변경
- 수치 조정은 **배율(`balance.mult`, `tuned_power_mult`, `enemy_power_curve`)**로 하고, 데이터 정의는 가능한 한 건드리지 않는다.
- 러너 실행 → `data/*.json`의 배율 갱신 + `sim/reports/*.json` → `python3 sim/report_md.py && python3 sim/fill_doc.py` → 문서 반영.
- 라이브에는 **BalancePatch JSON**(21 §6, `NetDtos.BalancePatch`)으로 서버 `/config/balance`에 올린다. 앱 업데이트 없이 적용되며, 전투 세션은 시작 시점 버전에 고정된다.
- 전투 규칙(엔진) 자체를 바꾸면 `python3 sim/make_vectors.py`로 벡터를 다시 만들고 C# 코어를 동기화해 EditMode 벡터 테스트를 다시 통과시킨다.

### 3.3 디자인 토큰·테마
`design/tokens.json` 편집 → `python3 tools/gen_csharp.py` → `unity/UI/theme.uss`, `DesignTokens.cs` 복사. 화면별 UXML/USS는 Unity 프로젝트에서 작성하되 색·간격·폰트는 토큰 변수만 쓴다(12 §3~§6).

### 3.4 문자열·로컬라이즈
UI 문구는 `tools/strings_en_1.py`의 `UI` 사전(ko, en), 데이터 문구는 원본 데이터 → `python3 tools/gen_strings.py` → `data/strings_unity.csv` → Unity Localization String Table 임포트(키 = `ui.…`, `hero.H001.name` 등). 누락 키는 런타임에 `[key]`로 표시(23 §5 LOC).

`server/openapi.yaml` 편집 → `python3 -m pytest tests/test_openapi.py` → `python3 tools/gen_netdtos.py` → `NetDtos.cs` 복사 → 목 서버 재기동(`npx @stoplight/prism-cli mock server/openapi.yaml`) → 서버 구현 동기화. 필드 추가만 하위 호환이다(21 §3).

### 3.6 아트

## 6. 함정과 FAQ
- **벡터가 안 맞는다**: 이벤트 체크섬의 `by_type` 개수부터 비교해 첫 불일치 틱을 찾는다. 흔한 원인: `float` 혼입, 나눗셈 순서 변경, 정렬 타이브레이크의 RNG 호출 순서, 딕셔너리 순회 순서, `Math.Round` 모드, 틱 홀짝 순회 방향(짝수 정방향·홀수 역방향).
- **시드가 JSON에서 깨진다**: 서버는 시드를 2^53 미만으로 발급한다(21). 그래도 `long`으로 받고 `ulong`으로 캐스팅한다.
- **gen_heroes를 돌렸더니 밸런스가 사라졌다**: 정상이다(§1 주의). `sh sim/run_hero.sh`와 `sim/run_traits.py --iters 2 --fights 600`을 다시 돌리거나, 커밋에서 `heroes.json`·`traits.json`의 `balance`를 되돌린다.
- **팀 슬롯과 최소 인원이 충돌한다**: 참전 슬롯 = clamp(max(레벨 슬롯, participation.min), min, max) (20 §4). 서버와 클라이언트가 같은 함수를 쓴다.
- **시간**: 모든 타이머는 서버 시각 오프셋 기준. 일일 리셋 05:00 KST. 기기 시각 금지.
- **상황 아이템**: `item.{id}.situational` 툴팁과 `ui.shop.tag.situational` 태그를 S10·S12에 표시한다(B8 §3).
- **1막 난이도**: 보통은 의도적으로 80~100%(온보딩). 긴장은 어려움·악몽이 맡는다(20 §5, B9).
- **Addressables 초기 용량**: 150MB 제한. 국가별 원격 그룹, 초상 아틀라스는 출신별 분할(15 §6.2).
